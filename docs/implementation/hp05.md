# HP05: render the actual brand Logo

## Dependencies and scope

This branch is stacked on HP04 `149bfd7` and the HP08 asset-reader dependency `639a665` (local cherry-pick `6dd606a`). The HP05 commit contains the Logo change only. No model calls, paid services, environment files, global installations, or running services were changed.

N14 now reads `BrandKit.logo.primary` and renders those pixels. The old generated circle-in-square mark has been removed. No image model draws or rewrites Logo text. The renderer preserves color and alpha, contains the image without changing its aspect ratio, retains existing transparent padding, adds the requested safe margin when needed, and never upscales a small source. Oversized, corrupt, animated, unsupported, empty, or fully transparent images fail explicitly. The accepted raster inputs are still PNG, JPEG, and WebP; SVG requires a separately reviewed rasterizer rather than executing arbitrary SVG content.

Local paths are restricted to the server project root. OSS/S3 use the HP08 reader and registered/server-configured stores, with an 8 MiB read bound. A `brand://` URI requires the explicit matching enterprise identity and the existing enterprise asset reader. The node cannot infer ownership from the URI itself. The source URI and SHA-256 remain in the packaging manifest.

## Missing input and preview semantics

- A declared real source that is missing, unreadable, unauthorized, or invalid raises a non-retryable error before a previous Logo render is overwritten.
- No BrandKit produces `logo_status=missing`; an explicit `mock://` source produces `logo_status=mock`. Both omit the Logo and empty opening card. They retain the CTA and canonical AI label so the rest of the zero-key preview flow can continue.
- `logo_status=ready` means a valid supplied Logo was read and rendered. It does **not** mean the full film passed final review. `preview_only` here describes the Logo-input limitation; HP06 must combine it with audio/visual provenance and final quality review before allowing real delivery.
- Logo placement honors the actual rendered width and the platform's right/top safe area. Centered opening/closing Logos keep the original source geometry.
- Safe-margin ratios at or above one half cannot leave a visible mark and fail clearly rather than silently changing the declared margin.

## Coordinated compatibility changes

`N14Input.enterprise_id` is optional for compatibility and required for `brand://`. Workflow N14 passes the request enterprise identity and saves `logo_status`; N15 receives it. PackageElement, N15Input, Timeline, and result carry `logo_status`. Older callers that pass N14 elements can recover the status from the closing CTA element.

The revision packaging call also passes the snapshot enterprise identity, so an authorized stored brand remains readable during Logo edits. N15's render QA permits an explicitly missing/mock unbranded **preview**, still requires a CTA, and rejects replacement Logo elements for that preview. Ready/unknown legacy inputs retain the original closing-Logo requirement. The composition/filter/audio logic is unchanged. HP06 owns the server-side real-delivery gate and must reject any Logo status other than ready.

The old N14/T09 tests compared a fabricated Logo with the same fabricated renderer. They now use an independently drawn, authorized local source and compare native-size output bytes directly with that source. N12's acceptance and real-audio fixtures now supply an actual local Logo to preserve their original intro/outro timing assertions. No cut-count, timing, loudness, or ducking acceptance thresholds were reduced.
