# HP08：私有媒体、上传安全与真实参考输入

2026-11-01。本次对应审查 B01、B08、B12、L08、F15。保持品牌、DESIGN tokens、AI 标识与 SPEC 既有指标；不增加依赖，不读取 `.env`，不调用真实付费模型，不改变公开 bucket 或登录规则。

## 完成的行为

- 素材库图片使用当前会话的 Bearer 请求读取为 Blob；组件卸载、换图、重试时取消旧请求并释放 object URL。预览有加载、失败、重试反馈。类型切换时旧列表请求不会覆盖新列表。
- 素材文件继续校验企业归属，支持授权后的 Range 206 / 416，匿名 401、其他企业 404。返回 private/no-store 和 nosniff；不把会话令牌放进素材 URL。
- `/v1/assets` 在处理层按 64 KiB 读取，不再 `await file.read()` 整文件入内存。入口 ASGI 层同时限制声明长度和真实接收字节；`/v1/uploads` 同样保护。内容过大返回 `413 {"detail":"文件过大"}`；伪报长度和无长度分块请求也被限制。解析失败和中断关闭临时文件；普通附件处理层落盘失败也清理未完成上传。
- 上传按真实内容嗅探：图片实际解码并检查后缀；PDF、Office、音频和字体检查容器标识；不再把 PNG 改名 JPG 当作有效 JPG。文档/音频/字体嗅探不是完整解析或恶意软件扫描。
- 上传目录、企业素材目录、元数据与素材文件拒绝符号链接越界；修复“在自己上传目录放指向另一上传目录文件的链接”仍可能通过归属检查的问题。

## 真实参考输入调用链

1. 普通流程：`POST /v1/uploads` → 项目附件的服务端 upload_id → `activities.n08_keyframe` → `materialize_attachments` → N8 的 Pydantic `reference_images` → `gateway.generate_image` → Seedream `image`。
2. 画布图片：`ref_image → image` → 校验上传企业 → `materialize_reference` → `project/media/inputs/{sha256}.png` 等受控副本 → 私有 URI 参数 → Seedream adapter 内转 data URL。
3. 画布视频：`image → video` → 上游已选候选的私有 URI → Seedance `first_frame`。
4. 镜头换参考与重生：ShotDesk / 上游参考 upload_id → 同一复制函数 → `invoke_node → N8`。没有单独镜头参考时，重生保留项目原始附件参考。
5. N10 既有 opening/closing URI → Seedance 分别生成 `first_frame` 与 `last_frame` content 项，修复尾帧被忽略的问题。

本次明确配置参考能力的模型为既有默认 `doubao-seedream-4-0-250828`、`doubao-seedance-1-0-pro-250528`，以及仅首帧的 `doubao-seedance-1-0-pro-fast-251015`。未知模型、Fast 尾帧、错误 role、视频多参考参数等明确拒绝，不静默删掉输入。保持既有网关 fallback 规则；fallback/mock 不能当成真实模型效果验证。

## 私有媒体协议

`gateway.storage.AssetRef` / `read_asset_bytes` 是统一字节读取契约：

```python
read_asset_bytes(ref, *, store=None, allowed_roots=(), max_bytes=20 * 1024 * 1024)
```

- `oss://` / `s3://` 只读服务端配置的同桶 ObjectStore；拒绝跨桶和 query/fragment 凭证。S3 通过私有签名请求流式限量读取，不签发公开 URL。
- 绝对路径 / `file://` 必须位于调用者提供的服务端授权目录，且为常规文件；拒绝 HTTP、相对路径、远程 file host、FIFO 与越界链接。本地图片 adapter 进一步只接受本项目 `media/inputs`，不接受请求指定根目录。
- data URL 只在 adapter 发送体内生成；Invocation / 调用日志保留稳定私有 URI 与内容哈希文件名。本次路径不把 data URL、base64 或带会话的 URL 写入日志；网关其他调用入口的通用脱敏由 HP01 负责。
- 对象桶本身仍是现有共享后端。租户权限来自 API 先验归属和服务端已保存候选引用，URI 本身不授予权限；本次不声称新增了对象存储层的独立租户 ACL。

## 真实对象媒体的预览闭环

`workers.media.assets.materialize_project_asset(project_id, uri, gateway=None, max_bytes=...)` 将已确认属于当前项目候选的对象媒体缓存到本项目 `media/previews/{sha256(uri)}.后缀`，保持对象私有，之后由 FileResponse 处理 Range。

- 分镜在评审前物化选中的关键帧，卡片继续拒绝 mock URI 和纯色占位图；预览可用不会冒充“已评审”。
- 专家候选与用户创建的图片、视频、音频节点都有受保护的媒体路径。媒体接口从当前项目 checkpoint / canvas 中查 candidate_id，其他项目即使属于同一账号也不能用该 ID 越界读取。
- 缓存以生成对象 key 不变为前提；修改同名对象后的缓存失效与项目媒体回收不在本次范围。

## 限额与供应商文档核验

以下工程保护值不是 Apple 官方指标或认证，也不替换 SPEC 的产品验收指标：素材库保持现有 20 MiB；普通附件保持现有默认 8 MiB 及配置；请求包络另容忍 64 KiB；项目预览单文件上限 256 MiB。图片输入共同使用 10 MiB / 3600 万像素保护；这与 Seedream 文档约束一致，对 Seedance 是本应用采用的更保守共享输入上限。

2026-11-01 核验火山官方文档：

- [Ark 视频生成 API](https://console.volcengine.com/ark/region:cn-beijing/docs/create-video-generation-task-api)：`content` 的 image_url 支持图片 Base64，首尾帧用 first_frame / last_frame。
- [Ark 视频模型能力表](https://docs.volcengine.com/docs/ark/video-generation-tutorial?lang=zh&redirect=1)：1.0 pro 支持首尾帧，1.0 pro fast 不支持尾帧。
- [Seedance 1.x 官方输入要求](https://docs.volcengine.com/docs/lake-ai-service/seedance-video-generation-doubao-series?lang=zh)：当前模型首帧 1 张 / 首尾 2 张，尺寸 300–6000、比例 0.4–2.5；adapter 在发请求前检查。
- [Seedream 官方图像参数](https://docs.volcengine.com/docs/lake-ai-service/image-generation-seed-ream-series-models?lang=en)：image 支持字符串或数组的 URL / Base64；4.0 多参考最多 14 张，边长大于 14、比例 1/16–16；adapter 对真实字节检查并统一为 PNG data URL。

本次没有升级默认模型、接入 3D、多模态视频/音频参考或使用 live 请求。这些模型的真实质量、耗时和计费仍需后续经授权的集成验收。
