# HiLatv 创作者深度方案：吸收 LibTV 优点、反超它的缺点

> 版本：V1.0（2026-11-03）
> 作者：研发（接管 HiLatv 的开发）
> 依据：song 提供的 [LibTV 实测文章](https://blog.csdn.net/weixin_49199926/article/details/159393518)、[品玩 LibTV 深度评测](https://www.pingwest.com/a/312278)、[Seedance 故事板工作流](https://www.seedance.tv/zh/blog/seedance-storyboard-workflow-2026-zh)、公开的 LibTV Agent prompt 模板库，以及我们自己的代码与真实验证记录。
> 说明：只吸收**编排方式、字段结构、工作流思想**；不复制 LibTV 的代码、文案、素材、提示词原文。所有模板都由我们重新设计。

---

## 0. 一页结论

1. **LibTV 的本质**：无限画布 + 节点工作流 + 精细工具（九宫格/多角度/打光/宫格切分）+「故事脚本→分镜→批量出图→批量出视频」+ Agent 接入。它把「抽卡」变成「先规划、再生成、逐节点调整」。
2. **LibTV 的软肋**：
   - 对普通用户门槛高（节点编排是一套新语言）；
   - 场景/人物一致性仍靠人工反复调（三视图、锚点图、提示词）；
   - 镜头之间衔接、剧集连续性要人工精调；
   - 企业级能力弱：品牌资产、权限、审计、AI 标识、交付核验、成本透明基本没有；
   - 成本不可控：抽卡与批量生成很容易烧钱，没有预算闸门；
   - 剧本层薄：大纲→分镜，没有分场/人物/台词/版本/连续性管理。
3. **我们的机会**：做「**企业最简单的自动挡 + 创作者最深的专业挡，同一套数据、同一本账**」。
4. **落地抓手**：先把**分镜表**做成 Seedance-ready 的可编辑标准（P0），再做剧本与连续性（P1），最后做精剪/协作/规模化（P2）。

## 1. LibTV 凭什么成立（我们要吸收的优点）

| # | 优点 | 具体表现 | 我们怎么吸收 |
|---|---|---|---|
| 1 | 画布编排 | 无限画布、双击加点、五种节点（文本/图片/视频/音频/脚本）、多节点批量生成 | 已有画布，继续补齐多选批量生成、批量重跑 |
| 2 | 工作流模板 | 预置 4 种工作流，社区工作流一键复用 | 做「行业+体裁」模板库（广告/短剧/电商/口播），套用即生成项目 |
| 3 | 故事脚本节点 | 输剧本→自动拆分镜→批量出分镜图→批量出视频 | 升级为**剧本/分镜表**双层结构（见第 5 节） |
| 4 | 精细图片工具 | 高清、扩图、重绘、擦除、抠图、**打光（3D 光球）**、**多角度** | P1 做「打光/多角度」提示词化 + 参考图槽位，不做纯 UI 花活，直接接进生成链路 |
| 5 | 分镜工具集 | 多机位九宫格、剧情推演四宫格、25 宫格连贯分镜、宫格切分 | 我们已有「/ 专业功能」菜单；补齐后端真实能力与切分后自动建节点 |
| 6 | 逐镜可控 | 单镜改提示词重生成、局部重绘、只取宫格中某一格 | 分镜表逐行编辑 + 单镜重生成 + 局部参考图选择 |
| 7 | 改动后可重跑 | 改一个节点，重跑整条工作流 | 已有「重跑节点/下游」；补「只重跑选中镜头」与断点续跑 |
| 8 | Agent/API | Access Key + Skills，让 Agent 建项目、跑工作流 | 我们已有 Agent 入口与内部接口；P2 对外开放 Skills，但**绑企业权限与预算** |
| 9 | 拉片 | 上传参考视频→拆成分镜表（景别/运镜/提示词） | P1 做「对标拉片→复刻分镜」，接企业案例库 |
| 10 | 模型广度 | 可灵/ Wan / Seedance / Seedream 等 | 我们网关已多厂商抽象；按任务自动选模型并显示价格 |

## 2. LibTV 的缺点/用户痛点，以及我们怎么把它变成优势

| # | LibTV 的问题 | 用户真实感受 | 我们的反超设计 |
|---|---|---|---|
| 1 | **门槛高**：画布/节点/工作流是技术语言 | “我是编剧/老板，不想学工作流” | **双模式**：企业简单模式（一句话→成片）；创作者模式才出现分镜表/画布。同一项目随时切换。 |
| 2 | **抽卡烧钱、成本不可见** | “生成 20 次才中一条，账单看不懂” | 生成前**成本预估**（按模型/秒/张实时算）；预算上限→超限自动降档（先用便宜模型/低清草稿，确认后再高清重跑）；每镜花费可查。 |
| 3 | **一致性靠人肉**：角色/产品/场景跨镜漂移 | “主角每镜换张脸” | 角色卡+三视图+场景锚点+道具 in-scene 图，**绑定到分镜表槽位**；生成前自动检查“缺锚点/缺参考图”并提示。 |
| 4 | **镜头衔接差**：场景切换生硬 | “做单条可以，连成剧就散” | 分镜表内置**转场字段**（动作/形状/颜色/运动/缩放匹配）+ 上一镜末帧作为下一镜首帧的「顺接」开关；合成时按转场渲染。 |
| 5 | **剧集连续性弱**：服装/道具/时代感漂移 | “短剧第二集人就变了” | P1 做**连续性检查清单**（服装/发型/道具/场景/光线/时代词）自动扫描分镜表并标红；提示词编译器把锚点重复注入。 |
| 6 | **剧本层薄**：只有大纲→分镜 | “分场、人物小传、台词节奏没法管” | 剧本层：分场、人物、台词、节拍（钩子/冲突/反转/落点）；AI 可“拆场→分镜”“按节拍重写”；支持导入导出。 |
| 7 | **企业能力弱**：无品牌资产/权限/审计/交付门 | “公司要合规、要审、要追责” | 我们已有：品牌资料、成员权限、AI 生成标识强制、交付核验门、预算账本、离职交接；把这些接进创作者流程（每个分镜表带品牌约束）。 |
| 8 | **资产散落画布**：项目一多就乱 | “三个月后找不到素材” | 项目/分镜/镜头素材统一编号（项目→场→镜→版本），素材库自动归档，可被分镜表引用。 |
| 9 | **失败无兜底**：生成失败/超时只能重来 | “一晚上白等” | 已有操作幂等（operation_id）、失败重试、断点续跑、长任务后台；分镜表显示每镜状态（排队/生成/失败/可重试）。 |
| 10 | **无中文短剧/广告方法论** | “工具是通用锤子” | 内置体裁模板：企业宣传片、电商带货、短剧黄金 3 秒、口播、漫剧；每个模板自带分镜节拍与 Seedance 参数。 |

## 3. 我们的产品形态：三层模式，一套数据

```
┌─────────────────────────────────────────────────────────────┐
│  同一个项目（project_id）                                    │
│  同一套数据：剧本 / 分镜表 / 镜头 / 候选 / 版本 / 账本        │
├───────────────┬───────────────────────┬──────────────────────┤
│ 自动挡（企业） │ 专业挡（创作者）        │ 接口挡（Agent/API）   │
│ 首页一句话     │ 画布 + 分镜表 + 剧本    │ 一句话/剧本 → 自动跑  │
│ → 自动出片    │ → 逐镜可控 → 精剪导出   │ 到待复核/交付         │
└───────────────┴───────────────────────┴──────────────────────┘
```

- 企业老板：永远只看到「一句话、选比例/时长、等成片、下载」。
- 创作者：看到「剧本 → 分镜表 → 逐镜生成 → 合成/精剪」。
- 模式只是**视图切换**，不迁移数据；企业客户也能在需要时切到专业挡精修。

## 4. 分镜格式标准（对齐 Seedance，P0 核心）

### 4.1 三层结构

```
Project
 └─ Script（剧本）
     ├─ meta：标题/体裁/时长目标/比例/语言/基调/受众/平台
     ├─ scenes[]（场）
     │   ├─ scene_id / 场次 / 地点 / 时间 / 内外景 / 氛围 / 场景锚点图
     │   └─ shots[]（镜）
     │       ├─ shot_id / 序号 / 时长（3–10s，默认 5s）
     │       ├─ 内容层：purpose（钩子/卖点/证明/行动/转场）、visual、dialogue、on_screen_text
     │       ├─ 镜头层：shot_size、camera_move、camera_angle、lens、composition
     │       ├─ 美术层：lighting、mood、color、style_ref
     │       ├─ 连续性：character_ids、scene_id、prop_ids、wardrobe、continuity_notes
     │       ├─ 参考图槽位：first_frame、role_sheet、scene_anchor、prop_in_scene（各自可空）
     │       ├─ 音频：voiceover（配音）、sfx、bgm_mood、silence
     │       ├─ 转场：transition_in/out（cut/动作匹配/形状匹配/颜色匹配/缩放匹配）
     │       └─ 生成参数：model、ratio、resolution、duration、seed、negative
     └─ style_bible（全片质感词：2D 绘本 / 写实电影 / 广告质感…）
```

### 4.2 我们自己的分镜表字段（代替 LibTV 的表格）

| 分组 | 字段 | 说明 |
|---|---|---|
| 基本 | 镜号、场次、时长、目的 | 目的决定这一镜的任务（钩子/卖点/证明/行动） |
| 画面 | 画面描述、景别、机位、运镜、构图 | 写「看得见」的东西，不写抽象情绪 |
| 美术 | 光线、氛围、色彩、质感词 | 全片质感词固定，不逐镜漂移 |
| 人物/场景 | 角色卡、场景锚点、道具（in-scene） | 槽位绑定，生成时自动带参考图 |
| 台词 | 旁白、字幕、音效、BGM 情绪 | 屏幕文字只走后期叠加，不让模型画字 |
| 连续性 | 服装、发型、道具状态、与前镜关系 | 自动检查清单 |
| 转场 | 出点转场 + 入点转场 | 合成时执行 |
| 生成 | 模型、比例、清晰度、时长、首帧来源、负面约束 | 单镜可覆盖全片默认 |

**示例（JSON 精简）**

### 4.3 Seedance Prompt 编译器（关键差异点）

我们不把「一段自由文本」丢给模型，而是由编译器从分镜表字段拼出结构化提示词：

```
[任务] 这是一个{体裁}短片的第 {order}/{total} 镜，{duration} 秒，{ratio}。
[主体] {主体描述}；参考图槽位：角色卡={有/无}，场景锚点={有/无}，首帧={有/无}。
[场景] {地点}，{时间}，{内外景}，{氛围}。
[动作] {这一镜发生什么变化}。
[镜头] {景别}，{机位角度}，{运镜}，{构图}。
[光线/风格] {lighting}，{style_bible}，{mood}。
[连续性] 与上一镜{关系}；保持{角色/服装/道具/场景}不变；{continuity_notes}。
[约束] 画面无任何文字/数字/字母/水印/标志；屏幕为纯发光不显示内容；手部自然；产品形状稳定。
```

编译器规则（吸收 Seedance 实践后我们自己的版本）：

1. **一镜一任务**：每镜只承担一个目的，提示词不堆叠多个动作。
2. **正向穷举代替负面禁用**：需要排除元素时，写「画面里有且只有 A、B、C」，不在提示词里提不要的东西。
3. **参考图职责显式声明**：角色卡只取脸/发型，场景图只取布局，道具图只取外形；换装镜写「衣服不按角色卡」。
4. **零文字铁律**：画面文字一律后期叠加；屏幕/单据/招牌写「纯发光/空白/横线示意」。
5. **时长约束**：Seedance 2.x 只接受 5/10 秒（我们已在网关按此归一），分镜表默认 5 秒并提示超时拆分。
6. **连续性锚点重复注入**：同一角色/场景的锚点描述在每镜重复，不靠模型记忆。
7. **风格不漂移**：质感词全片固定，不逐镜换风格（除非剧本刻意做反差）。
8. **每次生成保存 prompt_parts**：让用户看到「这句话是哪来的」，可单段改写、可 A/B 对比。

## 5. 可编辑性设计（song 最关心的点）

### 5.1 三个编辑入口，同一份数据

| 入口 | 适合谁 | 能力 |
|---|---|---|
| 分镜表（表格） | 编剧/导演/广告策划 | 逐行改所有字段；增删镜头、上下移动、复制；批量设比例/时长；一键生成选中镜头 |
| 画布（节点） | 视觉创作者 | 看图选片、单镜重生成、局部参考、多机位/九宫格、打光 |
| 剧本（文档式） | 制片/文案 | 分场、台词、节拍；AI 拆场→分镜；导入/导出 |

### 5.2 AI 辅助编辑（人只做判断）

- 「这一镜画面再冷一点」→ 只改 lighting/mood 字段并预览新 prompt，不直接烧钱；
- 「拆成两个镜头」/「合并这两镜」→ 自动均分时长、重新编号；
- 「按这个参考视频的风格重写分镜」→ 拉片结果→ 对齐字段；
- 「这段旁白太长」→ 提示超时长并给 2 个缩短版本；
- 所有 AI 修改都**先预览 diff**，确认后再生成。

### 5.3 版本与对比

- 每个项目保留剧本版本、分镜表版本、每镜候选版本；
- 可「恢复上一版分镜」「对比两版提示词」「同镜多候选并排」。

## 6. 分阶段落地

### P0（建议立刻做，1–2 周）

**目标**：分镜表可编辑 + Seedance-ready 格式 + 单镜生成闭环。

交付：
1. 数据结构与接口：`GET/PUT /projects/{id}/script`、`POST /shot`、`PATCH /shot/{id}`、`DELETE`、`POST /reorder`、`POST /split`、`POST /merge`、`POST /shots/{id}/generate`；
2. 分镜表页面（创作者模式）：表格编辑、拖拽排序、批量选择、状态显示、单镜生成；
3. Seedance Prompt 编译器 + prompt_parts 存储 + 预览；
4. 单镜生成走真实 Seedance（时长归一 5/10s、首帧槽位、参考图槽位）；
5. 企业模式不受影响（默认隐藏分镜表）；
6. 验收：同一项目，企业模式一句话能出片；专业模式能改分镜并只重生成一镜；改完能合成；成本可见。

### P1（2–3 周）

1. 剧本编辑器（分场/人物/台词/节拍、AI 拆场）；
2. 角色卡/场景卡/道具卡 + 三视图/锚点图；连续性检查清单；
3. 拉片：上传参考视频 → 分镜表（切镜、景别、运镜、字幕、提示词）；
4. 批量生成队列、失败重试、断点续跑、成本预估；
5. 分镜导入/导出（JSON/CSV/Markdown）。

### P2（1–2 月）

1. 时间轴精剪（多轨音效/字幕/转场/配乐）与多版本导出；
2. 企业模板库（行业+体裁）、案例复用；
3. 协作：批注、审阅、版本对比、成员权限接入；
4. 对外 API/Skills（绑权限与预算）；
5. 质量闭环：自动 QA + 人工复核 + 交付核验。

| 真实模型 | ✅ 文字/图片/视频/配音均验证 | 全片串联（已定位并修完主要问题） |

## 8. 与 LibTV 的差异化卖点（对外可以这么讲）

1. **老板模式**：一句话出片，不需要学画布（LibTV 要给 Agent 或自己搭工作流）。
2. **编剧模式**：分镜表逐行改，改完只重跑一镜，不重新抽卡。
3. **企业级合规**：品牌资产、AI 标识、授权音色、成员权限、交付核验，全流程内置。
4. **成本可控**：生成前报价、预算上限、超限降档、每镜账单（LibTV 抽卡账单不可控）。
5. **连续性工程化**：角色/场景/道具锚点 + 自动检查 + 转场匹配，专治“连成剧就散”。
6. **一套数据三种用法**：企业客户、创作者、Agent 共用同一项目，不迁移、不重复生成。
7. **中文短剧/广告模板**：内置黄金 3 秒、卖点结构、口播、漫剧模板（不用自己搭工作流）。
8. **可解释的 AI**：每个镜头提示词可拆解、可改、可对比（不把提示词藏在黑盒里）。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| LibTV 也在快速迭代 | 我们不打「功能数量战」，打「企业落地 + 成本可控 + 可编辑分镜」差异化 |
| 模型价格/能力变化 | 网关已抽象多厂商；价格表可配置；模板与模型解耦 |
| 分镜表字段过多，用户不会填 | 默认值 + AI 填充 + 只暴露「必填 5 项」，其余折叠 |
| 真实生成成本高 | 草稿模式（低清/便宜模型）→ 确认后高清重跑；预算闸门 |
| 与 LibTV 格式对齐引发「抄袭」误判 | 只对齐字段/工作流思想，模板文案与代码全部自研；对外说明差异 |
