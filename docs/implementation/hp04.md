# HP04: preserve real voice audio through N6 / N12 / N15

## Scope and assumptions

- Depends on the HP08 asset reader (`639a665`, cherry-picked here as `6dd606a`).
- No live provider requests, secrets, environment files, deployed services, or paid calls were used.
- Local media roots come from the server's `HILATV_PROJECT_DIR`, never a request-provided allowed-root list. OSS/S3 use registered gateway stores or server object-store configuration and the HP08 bounded reader.
- Mock audio is allowed only for an explicit gateway mock result, a persisted mock take, or the explicit offline mode. It retains `mock`/`mixed` provenance; it is not evidence of a real commercial delivery.

## Result

N6 now decodes the actual TTS asset, including authorized local files and stored objects. N12 loads every spoken shot's actual bytes before requesting music, measures the duration, and places the entire take on the aligned shot clock. Missing, corrupt, truncated, silent, duplicate, unauthorized, or duration-mismatched takes fail explicitly; no replacement narration tone is generated. Narration normalization, measured ducking, and master loudness keep their existing targets.

N12 consumes actual music bytes when the gateway returns a non-mock result. Generated test music remains restricted to explicit mock results. The internal sound-effect catalog remains a test fixture: outputs using it retain mock/mixed provenance; a live result without explicit mock fallback cannot silently use it as a licensed sound-effect source.

N15 consumes the N12 mix itself, retaining its provenance. If no mix is supplied, it decodes the actual N6 takes and places them after the intro at their shot offsets without truncating speech. Existing aligned-script mapping moves subtitles and packaging onto the same clock. Original take data is unchanged.

Compressed media is decoded from a temporary seekable file (MP4/M4A may put the index at the end), with timeout/duration limits and a media-format/protocol allowlist. Playlists cannot cause external file/network fetches. The temporary file is removed after decoding.

New optional schema fields preserve backwards compatibility: take `provenance`/`seed`, audio-track `provenance`/stem paths, and timeline/result `audio_provenance`. N6 marks mock ASR as `not_verified_in_mock`, and missing ASR provenance as `not_verified`; only an explicitly real ASR result receives `verified`.

## Existing hard-cut regression: cause and repair

The original N12 hard sample failed before this change and during expanded regression. This was traced to the cut detector, not attributed to an FFmpeg version. Decoding the source, master, and no-subtitle outputs showed eight real low-contrast shot changes at step strengths 10.28–10.60; the brighter outro was 34.07. The detector used the maximum of the whole film times 0.35 (11.93) and suppressed all eight shot changes. Frames, source patterns, and edit joins were present; master/nosub had the same failure.

The detector now uses typical candidate contrast rather than one outlier's peak, with spatial block medians to reject local subtitle/badge pops. The absolute floor 6, relative factor 0.35, noise factor 6, 80ms duplicate interval, and acceptance thresholds (at least eight hard-sample changes, beat error at most 80ms) are unchanged. Additional regressions cover a bright outro, local subtitle panel, sustained motion/noise, and a single genuine frame change. On the existing encoded hard sample, the nine detected changes are independently compared with decoded music onsets; the measured maximum gap is 33.31ms.
