# HP02 草稿恢复补丁

2026-11-02，基于 `3314b15`。本提交只处理 ProjectDraft 传输/路由会话、首页、方案页及恢复界面，不改 Canvas、Storyboard、后端、共享进度或依赖。

## 复现与修复

1. 旧 hook 在 A 保存未返回时切换到 B，旧 ACK 会把 B 的 project_id 改成 A，随后把 B 文本 PUT 到 A。现在每个 props 路由身份拥有独立 ProjectDraftSession；在 props 改变的这一帧同步废弃旧会话，新 ready 为 false。旧 flight / ACK / 保存循环无权更新新会话。
2. 旧异步本地写入可能晚于新路由恢复。现在保存时及 IndexedDB 真正打开后都检查同一 epoch；失效写入只放独立 backup key，不写 home 或任何 project 主记录，避免 A→B→A 时覆盖新输入。
3. 首页恢复前上传、链接和分镜选项原先仍能编辑，随后被异步恢复覆盖。现在所有持久输入统一以 editable 准入，恢复/版本选择/提交期间禁用；普通自动保存期间仍可继续输入，旧 ACK 只合并上传标识及服务端版本。
4. HomeStudio / ConceptBoard 的方案请求、开始生成、异步存储与 router 跳转都检查会话 ticket。旧结果不能改变新路由，旧 finally 也不能释放新操作的 busy 锁。

## 真冲突与丢 ACK

- 保留 POST 创建的冻结快照和原 operation_id，不修改现有创建幂等语义。
- PUT 仍使用原 revision / 完整输入重试；已提交但丢回执的恢复由并行后端原子 receipt 完成：仅当前版本等于 base+1 且完整规范化字段哈希一致才返回原 ACK，不递增版本。
- 真 409 使用 detail.snapshot 解析服务器内容，停止自动重发旧 revision。界面同时展示双方文字、文件名、上传状态、链接及分镜选项。
- “采用服务器版本”先等待 IndexedDB 写入完整本地副本，含实际 File 字节；备份失败则不替换。副本可以在同一项目再次打开后恢复，再与当前服务器核对。
- “用我的修改继续保存”才按用户刚核对的服务器 revision 保存。服务器若再次改变，重新展示双方内容，不偷偷抬高 revision 再发送。
- 无权限或暂时读取失败的现有项目保持不可提交，不会另建项目替换。恢复失败可重新恢复，不保留一个永久 rejected flight。

## 未确认的开始生成

先保存文字/附件，再持久化 submission_pending 与 start_operation_id，然后发送开始请求。未收到确认时保留原编号和输入并冻结编辑；刷新后先查询原项目状态。重试沿用原提交，不再先改草稿或另建项目。

只有服务端确认 submitted 且本地确认记录也完成写入后，才把本地标成 started。最终本地写失败仍保留 pending，可以继续确认。用户可以打开原项目，或核对服务器确认仍可编辑后明确选择版本；不会因界面状态而清掉待确认输入。

## 验证与边界

`lib/project-draft.test.ts` 共 20 项（新增 16 项）覆盖：旧 A ACK 不污染 B、延迟本地写不写新主记录、保存期间继续输入、冻结创建 ACK、恢复失败后重试、未授权项目不替换、冲突显式选择与二次冲突、真实文件字节备份/重载恢复、备份失败不替换、丢 PUT ACK 原输入/版本重试、开始提交 pending 重载、最终本地写失败保持 pending、不借其他操作的提交编号清掉本地未提交的新输入。

已执行 `npm run test:unit`（既有 Node 单测及 54 项 Vitest 全部通过）、`npx tsc --noEmit`、本次六个前端文件的 ESLint、`git diff --check`。没有构建/重启父正在联调的服务，没有付费调用或新增依赖。浏览器联调在父分支集成后继续，不能以这些单测替代真实 IndexedDB、路由、文件选择和提交回执联调。

会话失效时的输入保存为独立可恢复副本，不作为新页面的主草稿。副本暂未自动回收；现有 draftScope 仍按会话令牌哈希隔离，长期账号/令牌迁移策略属于身份任务。本补丁不改变服务器内容安全、预算、工作流提交或模型生成策略。
