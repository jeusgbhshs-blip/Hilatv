2026-11-01。本次按 HP07 / BE-11 实施，补 HP03 剩余的 B10 worker 顺序问题。基线为 HP08 `1d5ed15`，本地先 cherry-pick HP03 `b60dd35` 为 `0a5d021`。不修改前端、Makefile、共享进度，不增加依赖或执行真实供应商请求。

## 前端请求合同

以下两个 POST 增加可选字段 `operation_id: string | null`：

- `/v1/projects/{project_id}/canvas/nodes/{node_id}/generate`：原有 prompt / count 保持兼容。
- `/v1/projects/{project_id}/shots/{shot_id}/regenerate`：原有 narration / prompt_suffix 保持兼容。

编号长度 1–128，匹配 `^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$`。建议客户端每次用户主动点击新生成时使用 `crypto.randomUUID()`；内部网络重试保持完全相同的 JSON body。缺省编号时服务端每次创建新操作，以兼容旧客户端；旧客户端不能依赖无编号请求实现网络幂等。

同一项目内 operation_id 绑定操作类型、目标和规范化请求。改变 prompt、count、narration、prompt_suffix 或复用到另一个目标，返回 409，`detail.code=operation_input_conflict`。同一编号不是“读取最新输入再生成”；需要使用新的编号发起新的意图。

成功结果保留原有 canvas、charged 等字段，并新增：

```json
{
  "operation_id": "客户端或服务端编号",
  "generation_id": "服务端稳定UUID",
  "input_revision": 12,
  "input_hash": "sha256",
  "operation_status": "succeeded",
  "replayed": false
}
```

成功重试返回该操作原有结果，replayed 为 true，没有新的模型调用或费用/次数扣减。charged 是这次逻辑操作的总次数，不是重放请求另扣的次数。重放的 canvas.layout_version 可能早于之后的编辑；前端不能让旧版本覆盖更新的草稿。

执行中断或结果无法确认时返回 409，detail 为带 message / code / operation_id / generation_id / input_revision / input_hash / operation_status 的对象，code 为 `operation_result_unknown`。界面应显示“结果待确认，等待恢复”，不要把它变成自动再次生成。message 位于 detail.message，不能仅解析字符串 detail。输入校验及预算拒绝沿用原有错误状态。

## 持久身份与新结果

- `generation_operations/{sha256(operation_id)}.json` 保存请求摘要、输入快照、输入版本、生成身份、状态、供应商输出来源和最终响应；使用原有项目锁与原子 fsync / rename。
- `generation_counter.json` 是项目单调序号，不在项目/版本快照中恢复。序号损坏则拒绝新生成；不会猜测回零。序号在受控 32 位种子周期内使用。
- 输入版本取当前 CanvasDoc.layout_version；input_hash 绑定实际有效提示词、镜头、参考资产、时长与所选输入。它不冒充未来 HP10 的全局项目 revision。
- 每个新操作得到服务端 generation_id 和新种子序列。N8 / N10 原有结构化模块与缓存保留，生成上下文显式传播到线程池；候选 UUID、种子及网关参数包含该次身份。
- 同一编号成功后直接重放持久响应；跨线程、跨 API 进程或换一个网关实例不会再调用模型。旧候选保留，新候选追加，旧镜头候选取消自动选中，仍可比较。
- 请求发送意图在任何潜在外部提交前持久化。进程提交后退出、超时或部分候选失败时，同编号不会再次盲目提交。已知的部分输出 URI 留在记录中供后续恢复使用。

## 来源与缓存证据

用户节点候选顶层、镜头候选 params 保留以下服务端字段：operation_id、generation_id、input_revision、input_hash、seed、execution_mode、mock、generation_source、generation_source_uri、provider、model、cache_hit、fallback_reason。

- execution_mode 为 mock / live / unknown，只根据实际网关响应的显式 mock true / false 判定；字段缺失或类型无效为 unknown，不补 false。
- cache_hit 仅在实际网关日志或响应有布尔证据时填布尔值，否则为 null。实际模型/供应商优先读取匹配 generation、节点和种子的网关日志，不把真实模型误标成 mock-image / mock-video。
- N10 裁切会改变 URI，因此来源除原始 URI 外也绑定本次节点与种子。generation_source_uri 保留原始私有输出，避免裁切后丢失 mock/cache 来源。
- 这些字段不接受客户端声明为质检依据，不设置 QA 通过。HP06 仍需检查实际媒体、授权、终审、成片哈希及受控可信证据。

## B10：先准入，后保存

镜头重生先在内存准备旁白和提示词，检查项目状态、镜头、参考文件企业归属、输入上限与人物授权，再准入项目重生次数。预算不够时不修改脚本、CanvasDoc、候选选择或项目媒体，也不复制参考图到项目。

项目次数使用既有 begin_batch / finish_batch，按 operation_id 绑定同一张图像+视频操作；既有规则仍是一次镜头重生最多扣 2 次，同编号只累计一次。授权失败不扣次数。普通画布初次生成继续使用原有规则，没有擅自新增 SPEC 未规定的重生扣数。

通过准入后冻结参考图并绑定内容哈希路径；两个生成节点均成功后才保存新的旁白、关键帧与视频 checkpoint。失败不会先保存新旁白或覆盖旧选择。已发生或不能确认的费用与次数不因失败、刷新或版本恢复而回滚。
