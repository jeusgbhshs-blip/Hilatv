## 3. 产品结构（重要，先理解再改）

**同一个项目的三种用法，不是三套系统：**

1. **自动挡（一句话成片）**：首页写一句话 → 跑完整条管线（N1 需求 → N4 脚本 → N5 分镜 → N8 关键帧 → N10 视频 → N6 配音 → N13 字幕 → N14 包装 → N15 合成 → N16 终审）→ 成片。mock 下会停在 `needs_human_review`，要人工放行。
2. **手动挡（专家画布）**：项目 → 打开画布，无限画布 + 节点（需求文本 / 参考图 / 图片 / 视频 / 音频 / 脚本 / 镜头 / 成片），可以加节点、生成、连线、逐镜重做、拖时间轴、打组存工具箱。
3. **Agent 挡**：空白画布 →「一句话出整条片」→ AI 自己跑完整条管线，跑到待复核时画布顶栏出现「人工放行，继续出片」，放行后继续合成。

**数据落点**：每个项目一个目录，画布在 `<项目>/canvas.json`（布局、用户节点、连线、时间轴入出点、单镜参数、重生次数）；管线节点在 `<项目>/nodes/*.json`；快照在 `<项目>/project.json`。企业隔离靠会话；画布读取/写入接口全部校验企业。

## 7. 已知坑（照着做，少走弯路）

### 7.1 会话与重启

- 会话是 API 进程内存里签发的；**API 一重启，浏览器里 localstorage 的 token 失效**，前端会重新开一个会话 → 旧项目“看不见”（会落到 mock 演示画布）。
- 演示/给客户看之前，**别重启 API**；如果重启了，让用户刷新、重新建项目。

### 7.2 构建与运行

- `next start` 正在跑时**不要 `npm run build`**：会破坏正在服务的 chunk，浏览器报 404/白屏。正确顺序：`pkill next-server` → `npm run build` → `npm run start`。
- 构建后如果页面白屏/`Failed to load chunk`：停掉服务、`rm -rf .next`、重新 build、重新 start。
- API 和 Web 都要监听 `0.0.0.0` 才能被别人访问；只监听 127.0.0.1 只有本机能开。

### 7.3 公网预览

- 临时隧道方案（tunnelmole / localtunnel / localhost.run / pinggy）**都不稳定**，会过期、会换地址、会被墙/限速；朋友预览可以用，但不能当正式环境。
- 本轮可用的 localtunnel 地址（需要 tunnel 密码，密码是本机公网 IP `66.253.43.203`，会变）：
  `https://five-clowns-heal.loca.lt`
- 正式方案需要部署到服务器（花钱、要域名和 HTTPS、要访问密码/登录），等 song 决定。

### 7.4 环境差异

- 本机 ffmpeg 4.4、无 tesseract：本机有 2 项后端测试失败，不代表代码坏。
- Playwright 1.64.1 需要 chromium-1248；本机用 `channel:"chrome"` 绕过。CI 用 `npx playwright install`。
- 没有 Docker：`make up` 不可用，迁移只能用 `alembic upgrade head --sql` 生成 SQL 检查（本机已验证升降级 SQL）。
